# 原則 — なぜこの画面は「ちゃんとして見える」のか

実際に評価の高かった4画面（分析レポート・操作デモ・社内ダッシュボード・サービスLP）を Playwright で実測し、
共通していたことを14項目にまとめた。数値は実測値。

## 1. 結論を最初に置き、根拠をあとに並べる

- レポート: 表紙 → **数字4枚** → 目次 → 章。章の中は **図 → 読み取り（1〜2行）→ 表** の順
- デモ: 上部帯で「これはデモ」と言い切る → 進行ステップ → 画面と解説
- ダッシュボード: KPI（押すと該当の一覧へ飛ぶ）→ 要対応の一覧 → 推移
- LP: 1画面目で「何を・いくらで」まで見せる（料金の数字が最初の画面に入る）

読む人が最初の画面だけ見て閉じても、言いたいことが伝わる構成にする。

## 2. 色は「意味」に割り当て、ページ内で使い回さない

| 色 | 意味 | 例 |
|---|---|---|
| シアン `#00C8E4` | 通常・情報・進行中・区切りのアクセント | 章見出しの左罫、KPIの上罫、グラフの通常バー |
| マゼンタ `#E5006E` | ここを見て・料金・要対応 | ハイライトの1本、料金の数字、「未対応」チップ |
| イエロー `#FFD400` | 今・デモ・解説・注釈 | DEMO 帯、解説の吹き出し、表紙の上帯、「今週」 |
| インク `#101820` | 最重要の反転・主ボタン | 一番大事な結論カードだけ黒地に白文字 |
| ok / warn / danger | 状態だけ | 判定結果のタイル、エラー |

**1つの図でハイライトは1本だけ**。全部に色を付けると何も目立たない。残りは通常色かグレー。

## 3. 影ではなく「面」と「罫」で区切る

- spot 系はフラット: 影なし・角丸 4px（小物 2px）
- 区切りは **面の色の差**（背景 `#F3F6F7`/`#F5F7F8` の上に白、または白の上に薄い面）と **1px の罫線**
- 強調は **色付きの太い罫**: KPI は上罫 4px、章見出しは左罫 6px、問題の行は左罫 4px
- 社内ダッシュボードだけは例外的に 1px のごく薄い影（`0 1px 2px rgba(22,33,58,.05)`）まで可

## 4. 文字の段は少なく、差ははっきり

- 本文 15〜16px / 行間 1.75〜1.8（日本語は詰めない）
- 見出しは weight 900（h1）と 700（h2/h3）。サイズは h1 26〜40px（`clamp`）、h2 19〜24px、h3 17px
- 補足は 12〜13px、色は `--ink-2`（muted）。**文字色はインクと muted の2段だけ**。灰色を3段以上作らない
- 章の上に英字の小ラベル（eyebrow: 12px / 700 / `letter-spacing:.08em` / シアンの濃い色）。例 `SUMMARY` `BY SESSION`
- 見出しに `text-wrap: balance`

## 5. 数字は大きく・等幅で・単位は小さく

- KPI の数字は 30〜34px / 700〜900、単位は 14〜15px を横に
- `font-variant-numeric: tabular-nums`（必要なら等幅フォント）で桁を揃える
- 表の数字列は右寄せ（`td.r`）、`white-space:nowrap`
- 料金の数字は必ずマゼンタ

## 6. グラフは CSS で作れる形にする

- 構成比 → 100% 積み上げ帯（高さ 24px、角丸 2px）
- 項目比較 → 横棒（ラベル行の下に高さ 12px のトラック）、値は右に等幅で
- 推移 → SVG のスパークライン（線 1.6px ＋ 面 12% の塗り ＋ 末尾に点）
- 凡例は 12px の四角＋文字。グラフの下に「読み取り」を 1〜2 行で必ず書く
- ライブラリのデフォルト配色をそのまま使わない

## 7. 状態は色・文字・形の3つで示す

`最優先` `高` `中` `確認` のようなバッジ（文字）＋左罫の色（形）＋背景の淡色（色）。
色覚の違いがあっても、白黒印刷でも意味が通ること。

## 8. 誠実さもデザインの一部

- デモ・見本は上部に **DEMO 帯**（インク地＋黄色のタグ）で「架空」と常時表示
- データを載せたページには **出典・取得日・集計条件** をフッターか表の下に
- 「最終更新」は、複数のデータ源があるなら**一番古いもの**の時刻を書く
- 取れなかった数字を前回の値で埋めない。無いものは「—」と「取得できませんでした」
- 見本データに実在の会社名・個人名を使わない（「サンプル商事」「見本 花子」）

## 9. スマホで崩れない書き方を最初から

- グリッドは `repeat(n, minmax(0,1fr))`、子に `min-width:0`（長い日本語や数字で押し広げない）
- 720px 前後で 1〜2 列に落とす。2列の本文＋解説は 900px で縦積み
- 目次やタブは `overflow-x:auto` で横スクロールさせる（はみ出しは要素の中だけ）
- 表は `.tbl{overflow-x:auto}` の箱に入れ、列が多い表は `table{min-width:560px}` で潰れを防ぐ（スマホで1文字ずつ折り返す事故が起きる）

## 10. 操作できる物は大きく・反応が見える

- 高さ 44px 以上（ボタン 48px が基本）
- `:focus-visible{outline:3px solid var(--cyan);outline-offset:2px}`
- 選択中は `aria-pressed="true"` / `aria-current` をつけ、見た目もそれで切り替える（クラスではなく属性で）
- フィルタは pill（`border-radius:999px`）＋件数

## 11. 1画面に主ボタンは1つ

主ボタン（インク地 or シアン地）は1つ。他は枠線だけ（`.btn.sub`）。CTA が並ぶときは主になるカードだけ 2px 枠。

## 12. ダークモードは「同じ意味の別の色」

ライトの色をそのまま反転しない。シアン・マゼンタはダークで明るく（`#29d3ea` / `#ff5aa6`）、
淡い面の色（tint）は暗い同系色（`#11303a`）に置き換える。黄色の面に乗る文字はどちらのモードでも `#101820`。

## 13. 動きは最小限

使うのは hover の背景変化、進捗バーの伸び（`.25s linear`）、ドロワーの開閉くらい。
`@media (prefers-reduced-motion:reduce)` で止める。スクロール連動アニメ・パララックスは使わない。

## 14. 1ファイル1スタイル・CSSを散らかさない

`<style>` は1つ。冒頭にレイアウトの意図を1行コメントで書く（例: `/* 左=画面、右=解説。狭い画面では解説を下に積む */`）。
トークン → ベース → 部品 → ページ固有 の順に並べる。

## AIっぽさの排除（見つけたら必ず消す）

| よくある出力 | 代わりにこうする |
|---|---|
| 紫〜青のグラデーション背景 | 単色の面。spot は白/薄グレー＋ブランド3色の面 |
| 絵文字のアイコン（✨🚀📊） | アイコン無し、または意味のある SVG（線 1.5〜2px） |
| 大きなぼかし影＋角丸 16〜24px のカード | 罫線 1px＋角丸 4px、強調は色罫 |
| 何でも中央揃え | 本文と見出しは左揃え。中央はヒーローの1行と CTA だけ |
| アイコン＋見出し＋2行説明の3カラムが延々続く | 数字・図・表で中身を見せる |
| 英語の大見出し（"Unlock your potential"） | 日本語で具体的に（「年末調整、依頼する前に設定の抜けを確かめましょう」） |
| 「〜を実現」「シームレス」「革新的」 | 何が・いくらで・何分で、を書く |
| ダミーの実績数字・架空の推薦文 | 数字は出典付きで渡されたものだけ。無ければ枠ごと出さない |
| グレーの文字が4段階 | インクと muted の2段 |
| 角丸・余白が場所ごとにバラバラ | トークン（`--r` / 4の倍数）だけを使う |
